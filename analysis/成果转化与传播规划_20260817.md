# CCIR / LRAT 成果转化与传播规划

> 状态：规划稿（2026-08-17）
> 目的：把比赛过程中产生的工程资产、实验证据和最终成绩，转化为更专业的文章/报告，并评估 workshop、开源工具、教学案例等衍生成果。
> 本文基于 `control/CCIR/LOG.md`、`control/CCIR/STATUS.md`、`control/CCIR/REGISTRY.md`、`report/` 和 `ai_core_ccir_defense_20260807/02_technical_report/` 整理。

## 1. 项目内容一句话

我们以官方 Agent 轨迹、Training pairs、离线语料和原始 Qwen3-Embedding-0.6B 为固定输入，构建了一条“来源审计 → query-disjoint 切分 → 1+5 加权对比训练 → 独立评测 → 冻结与可复现交付”的检索器训练链路，并在 CCIR 的 A/B 榜取得第一梯队成绩：A 榜 Total 40.6，B 榜三种 Agent 平均 Total 56.18。

## 2. 可转化的核心资产

| 资产 | 内容 | 转化价值 |
|---|---|---|
| 数据审计/Provenance | pair 行与 trajectory 事件对齐，96,366 stable / 138 ambiguous / 0 mismatch；corpus 全量文本校验 | 可写成“数据质量与可追溯性”方法论，也可做成开源审计工具 |
| Query-disjoint 切分 | normalized query 整组划分，train/dev/locked test overlap=0 | 防止 query 泄漏的通用数据处理方案 |
| 训练实现 | 全参数加权对比训练、跨卡负例、checkpoint 恢复、可复现 runner | 可直接作为 LRAT 复现/教学参考实现 |
| 门控实验体系 | 多组 500/1000-step 短训 + paired bootstrap gate，记录了大量“未通过”结论 | 负结果本身有学术价值，可做 reproducibility/empirical study |
| 正式模型 | M01/M07/M10/M12，公开 HF 与 GitHub | 可复现基准、后续研究的起点 |

## 4. 转化方向

### 4.1 专业文章 / 技术报告

已经具备中英文 technical report，下一步可按不同目标深化：

- **比赛技术报告（内部/组委会）**：已有 2 页版和完整版；建议保持“事实+边界”风格，补充最新高 LR 实验结果。
- **公开技术博客（知乎/微信公众号/Medium）**：标题建议《从 Agent 轨迹训练检索器：CCIR 冠军方案的工程细节》；内容强调可复现、数据审计、query-disjoint、负结果和跨 Agent 现象。
- **学术短文/Workshop Paper**：可投 IR/AGI 相关 workshop（如 SIGIR、CIKM、WWW、ACL 的 resource/reproducibility 方向）。定位不是“新算法”，而是：
  1. 对 LRAT 训练数据与流程的独立复现与审计；
  2. query-disjoint 评估协议对 Agent retriever 的重要性；
  3. 一组有门控的负结果，帮助社区理解哪些 trajectory 加权/清洗假设不成立；
  4. 一个可复现的开源实现与完整交付身份。
- **预印本（arXiv）**：若比赛/数据许可以及作者同意，可整理为英文 technical report 上传；需要先确认不违反比赛数据条款。

### 4.2 Workshop / 教学 / 分享

可以设计为 2–3 小时 hands-on workshop：

**主题**：从 Agent 轨迹到可复现检索器——一次完整的 IR 工程实战

**目标受众**：研究生、工程师、参赛学生；需有 Python/PyTorch 基础。

**内容模块**：
1. Agentic Search 与 LRAT 监督信号（20 min）
2. 数据审计与 query-disjoint 切分（30 min）
3. 1+5 加权对比训练与跨卡负例（40 min）
4. 短训门控与评测（30 min）
5. 冻结、HF/GitHub/ZIP 复现交付（30 min）
6. 自由实验/答疑（30 min）

**可落地形式**：
- 高校 IR/NLP 组会或课程项目；
- 学术会议 tutorial / hands-on session；
- 开源社区线上直播；
- 校内“AI 竞赛工程化”分享。

**现有基础**：已有 smoke 数据、100-step 训练脚本、dev 评测、冻结/validator 脚本，可快速做成 workshop 材料包。

### 4.3 开源工具 / 基准

- 将 provenance、query-disjoint split、paired gate、freeze validator 整理成独立 Python 包或 CLI，方便其他队伍/研究者复用。
- 公开 M10 作为 LRAT 数据上的可复现 retriever 基准，附带训练配置、评测脚本和模型卡。
- 若许可允许，发布“负结果实验配置”作为 benchmark 的扩展，帮助社区避免重复劳动。

### 4.4 适合参与的 workshop / 非正式发表渠道

> 以下按“领域 + 常见类型”给出参考；具体届次、截稿日期和是否 archival 以对应官网 CFP 为准。

| 类型 | 代表性渠道 | 为什么适合本项目 | 注意 |
|---|---|---|---|
| IR 会议 Workshop / Short Paper | SIGIR、ECIR、CIKM、ICTIR、SIGIR-AP 的 workshop 或 short/resource track | 本项目就是 retrieval + agent trajectory，主题高度匹配 | 正式会议 short paper 通常要求一定 novelty；workshop 更适合 case study / resource / reproducibility |
| NLP/Agent Workshop | ACL/EMNLP/NAACL 的 Student Research Workshop（SRW）、RAG/GenIR/Agent 相关 workshop | 可以把“Agent 轨迹 → 检索器训练”讲成 Agentic Search 的实证案例 | SRW 通常面向学生，接收短文、海报和展示，门槛较低 |
| Data-Centric / Reproducibility | NeurIPS/ICLR 的 Data-Centric AI、Reproducibility、Datasets & Benchmarks 类 workshop | 我们有 provenance、query-disjoint、负结果、完整复现包，天然适合“数据/复现”叙事 | 需要把“比赛方案”改写成“方法/数据/评测协议” |
| IR 评测社区 | TREC、CLEF、FIRE 的 participation report / lab overview | 如果后续参加某个 track，可以顺带发表系统描述短文 | 不是传统 workshop，但属于低门槛非正式发表 |
| 国内中文渠道 | CCIR（全国信息检索学术会议）、CCF 相关学生论坛、高校 IR/NLP 组 workshop | 中文写作成本低，适合第一次投稿/报告 | 需关注当年征文主题和是否接收“评测/竞赛系统报告” |

**建议优先顺序**：

1. **先投 IR 或 NLP 会议下的 workshop / SRW**，因为本项目已有完整 technical report，只需压缩成 4–6 页短文。
2. 若时间紧张，可以先用 **arXiv + GitHub + 博客** 作为非正式版本，再投 workshop 的 non-archival 通道。
3. 若希望突出“工程可复现”，优先选 **resource / reproducibility / data-centric** 类 workshop；若希望突出“Agentic Search 现象”，优先选 **agent / RAG / GenIR** 类 workshop。
4. 国内会议（如 CCIR）是低成本试水的好选择，也能积累答辩/报告经验。

### 4.6 EMNLP 2026 可关注 Workshop 清单

从 EMNLP 2026 已公布 workshop 列表中，和本项目最相关的是：

| Workshop | 为什么相关 | 建议 |
|---|---|---|
| **Insights**（Insights from Negative Results in NLP） | 我们有多组 gate=false 的负结果：坏正例清洗、unit-weight、search-stage 加权、多正例、offline flywheel 等 | **最匹配**，可以把论文定位成“对 LRAT 式检索器训练的负结果与实证分析” |
| **REALM**（Research on Agent Language Models） | 我们做的是面向 Agentic Search 的 retriever，训练信号来自 Agent trajectory | **主题很对口**，可以讲“从 Agent 轨迹训练检索器” |
| **GLM**（Grounding Language Models） | 如果强调“检索结果作为 Agent 的证据/grounding”，可以切入 | 次选，需要把叙事往 grounding 上靠 |
| **DocInsights**（Document Intelligence and Understanding） | 如果强调文档证据选择、passage 检索和文档理解 | 次选，看具体 CFP 是否接受检索系统报告 |
| **LUHME**（Language Understanding in the Human-Machine Era） | 如果讨论 Agent/人机交互中的查询与信息消费行为 | 可选，但不如前两个直接 |

**不建议优先投**：MathNLP、ArabicNLP、NLLP、WiNLP、BlackboxNLP、MRL、ClimateNLP、BabyLM、W-NUT、WOAH、MINT、SALMA、UncertaiNLP、PANDORA、WMT、FinNLP、WSLP 等，主题离检索/Agent 轨迹较远。

**行动建议**：
1. 先查 **Insights** 和 **REALM** 的 CFP 页面，看截稿日期、页数和是否接受“系统/复现/负结果”类投稿；
2. 如果时间紧，优先按 **Insights** 的格式写 4–6 页短文，因为负结果是我们最独特的素材；
3. 如果 REALM 更偏 Agent LM 且接受 resource/reproducibility，也可以作为第一目标。

## 6. 写作/表达时的原则

- 区分“已验证事实”“合理推断”“未知边界”，沿用 `analysis/v2_primary_source_research.md` 的口径。
- 不把 A/B 榜结果写成普遍性结论；A 榜只覆盖固定 Agent，B 榜三种 Agent 差异明显。
- 不把“短训门控未通过”隐藏掉；负结果反而是本文区别于普通比赛报告的价值。
- 不公开服务器路径、SSH、token 等私密信息；公开材料只使用 GitHub/HF/比赛公开信息。
- 所有哈希、commit、模型身份在发布前做 fresh read-back，避免旧副本误当最终版。
